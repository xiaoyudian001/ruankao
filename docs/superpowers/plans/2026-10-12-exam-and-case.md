# 多题型解析与案例逐问练习

用户已确认多题型方案，并要求随后完成共享背景、先答后看、教材点评及修改再评。

## 第一阶段：解析兼容

- [ ] 在 `textbook-bridge/test_exam.py` 增加完整主答案缺少可选标签、JSON兼容、非法引用、问答不生成单选练习的回归。
- [ ] `exam.py` 按题干确定选择/判断/填空/计算/问答/案例的作答要求；未知题型保持开放。可选练习失败保留主答案，但未闭合主答案及未知来源必须失败。
- [ ] 将引用图像来源的编号与实际使用原图的元数据统一：明确引用所提供图文来源时保留该原页，不为未知编号或未知图片自动添加证据。
- [ ] `single_pass_components.py` 写入运行提示；`bridge.py` 记录分类错误，显示格式、引用、超时等具体原因。同步本机与仓库副本，更新原有Langflow生成组件。
- [ ] 离线复现之前第二次模型输出；用现有单元测试保护截图与单次生成路径。

## 第二阶段：案例逐問练习

- [ ] 建立案例、独立小问、不可覆盖的提交记录三张表。案例背景最多4000字，小问最多8个、各1000字；答案最多5000字。
- [ ] `lib/cases/model.ts` 验证输入；`app/api/textbook/cases/route.ts` 保存、列表、读取、提交与推进。所有动作要求所有者，写请求验证同源；请求标识幂等且不能重用到另一答案。
- [ ] 每小问一次教材分析复用 `textbook_jobs` 的内部case任务；提交前不创建分析任务、不向浏览器发送分析。点评复用 `textbook_critiques` 队列，只从服务端保存的背景、小问、分析、来源创建。
- [ ] 新 `/cases` 页面保留现有品牌，提供创建案例、共用背景、逐问答题、参考分析与蓝色引用、每次提交的点评及再评。浏览器草稿仅是本地恢复，提交与点评永久保存在D1。
- [ ] Chat列表排除内部case分析任务；来源面板复用已验证的jobId与rank，不接受浏览器伪造教材证据。
- [ ] 使用真实路由和隔离SQLite验证权限、幂等、先答后看、共享背景、教材来源、错误恢复与多次提交；静态渲染和构建检查前端。
- [ ] 生成追加迁移并发布现有Sites项目；更新本机连接器、回归原问题及案例小问，不重新入库。中文文档记录新增功能及验证边界。

## 验收边界

答案和点评属于结合教材的辅助分析，无官方评分细则时不报精确分数。案例背景及作答是资料，不能覆盖系统指令。主答案校验保留来源约束；无教材依据时明确说明。模型调用沿用已授权的MiniMax图文路径，每次最多2张教材图。
